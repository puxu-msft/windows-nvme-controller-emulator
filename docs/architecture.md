# 系统架构设计

## 整体架构

本项目采用 **虚拟总线驱动 + 虚拟 PDO** 架构，这是纯软件虚拟存储设备的最佳实践方案。

```
┌─────────────────────────────────────────────────────────┐
│                    用户应用程序                          │
├─────────────────────────────────────────────────────────┤
│                    文件系统 (NTFS/ReFS)                  │
├─────────────────────────────────────────────────────────┤
│                    卷管理器 (volmgr.sys)                 │
├─────────────────────────────────────────────────────────┤
│                    分区管理器 (partmgr.sys)              │
├─────────────────────────────────────────────────────────┤
│                    磁盘类驱动 (disk.sys)                 │
├─────────────────────────────────────────────────────────┤
│  ┌───────────────────────────────────────────────────┐  │
│  │     Virtual NVMe Function Driver (vnvme.sys)       │  │
│  │  ┌─────────────┐  ┌─────────────┐  ┌───────────┐  │  │
│  │  │ NVMe 控制器 │  │ 命令处理器  │  │ 存储后端  │  │  │
│  │  │   模拟层    │  │  (Admin/IO) │  │  适配器   │  │  │
│  │  └─────────────┘  └─────────────┘  └───────────┘  │  │
│  └───────────────────────────────────────────────────┘  │
├─────────────────────────────────────────────────────────┤
│  ┌───────────────────────────────────────────────────┐  │
│  │       Virtual Bus Driver (vnvmebus.sys)            │  │
│  │           枚举和管理虚拟 NVMe 设备                   │  │
│  └───────────────────────────────────────────────────┘  │
├─────────────────────────────────────────────────────────┤
│              存储后端 (内存 / 文件 / VHD)                │
└─────────────────────────────────────────────────────────┘
```

### Windows 存储栈说明

| 层级 | 组件 | 职责 |
|------|------|------|
| 文件系统 | ntfs.sys, refs.sys | 文件和目录管理 |
| 卷管理器 | volmgr.sys | 管理卷设备，处理 IOCTL_VOLUME_* |
| 分区管理器 | partmgr.sys | 管理磁盘分区 |
| 磁盘类驱动 | disk.sys | 将文件系统请求转换为 SRB |
| **功能驱动** | vnvme.sys | 处理块 I/O 请求 |
| **总线驱动** | vnvmebus.sys | 设备枚举和 PDO 管理 |

## 驱动架构说明

### 为什么不使用 StorPort Miniport？

StorPort Miniport 驱动模型传统上主要用于真实硬件控制器，但 **Microsoft 官方支持虚拟 Miniport 驱动**。

通过设置 `PORT_CONFIGURATION_INFORMATION.VirtualDevice = TRUE`，StorPort 会以虚拟模式运行：
- 不需要真实 DMA 对象
- 不需要硬件中断
- 不需要内存映射 I/O 端口
- 初始队列深度自动设为 250 (物理设备为 20)

**虽然 StorPort Virtual Miniport 是可行的替代方案**，本项目选择虚拟总线方案有以下原因：
- 更直接控制设备枚举和生命周期
- 便于学习 Windows 驱动开发基础概念
- 不依赖 StorPort 框架的复杂性
- 适合教学和原型开发

> **备选方案说明**: 如果您需要企业级功能（MPIO 支持、高级队列管理、官方推荐架构），请参考 [architecture-analysis.md](architecture-analysis.md) 中的 StorPort Virtual Miniport 方案。

### 方案 A（本项目）：虚拟总线 + 功能驱动

| 组件 | 文件 | 职责 |
|------|------|------|
| 虚拟总线驱动 | vnvmebus.sys | 作为根枚举总线，创建/管理虚拟设备 PDO |
| 功能驱动 | vnvme.sys | 实现 NVMe 控制器逻辑，处理 I/O 请求 |
| 用户态控制程序 | vnvmectl.exe | 创建/删除/配置虚拟磁盘 |

### I/O 请求流转

```
应用程序 (ReadFile/WriteFile)
         │
         ▼
    文件系统 (IRP_MJ_READ/WRITE)
         │
         ▼
    卷管理器
         │
         ▼
    分区管理器
         │
         ▼
    disk.sys (创建 SRB - SCSI Request Block)
         │
         ▼
    vnvme.sys (将 SRB 转换为内部块请求)
         │
         ▼
    存储后端执行实际 I/O
         │
         ▼
    完成请求，逐层返回
```

**注意**: 虽然我们模拟 NVMe 控制器，但在 Windows 存储栈中，disk.sys 会将请求封装为 SCSI/SRB 格式发送给下层驱动。我们的功能驱动需要处理这些 SRB 请求。

## 核心组件

### 1. 虚拟总线驱动 (vnvmebus.sys)
- 作为根枚举设备安装到系统
- 响应用户态 IOCTL 创建/删除虚拟设备
- 为每个虚拟 NVMe 设备创建 PDO
- 管理设备实例列表
- 处理 PnP 和电源管理事件

### 2. NVMe 功能驱动 (vnvme.sys)
- 附加到总线驱动创建的 PDO 上
- 接收来自 disk.sys 的 SRB (SCSI Request Block) 请求
- 将 SRB 请求转换为内部块 I/O 操作
- 可选：实现 NVMe Pass-through IOCTL 供管理工具使用
- 管理存储后端的读写操作

### 3. NVMe 控制器模拟器 (Controller Emulator)
- 控制器寄存器模拟 (CAP, CC, CSTS 等)
- 控制器状态机管理 (Disabled → Enabling → Enabled)
- 能力报告 (Capabilities)
- Identify 数据结构填充

### 4. 命令处理器 (Command Processor)
- Admin Command 队列处理
- I/O Command 队列处理
- 完成队列管理
- 中断模拟 (MSI-X 模拟)

### 5. 存储后端适配器 (Storage Backend)
- **内存后端**：使用非分页池内存，适合小容量测试
- **文件后端**：使用文件作为存储介质，支持持久化
- **VHD 后端**：利用 Windows VHD API，可挂载现有虚拟磁盘
- 可扩展接口设计，支持自定义后端

### 6. 配置管理器 (Configuration Manager)
- 注册表配置读取
- 运行时参数管理
- 命名空间配置
- 动态容量调整

## 驱动类型选择

采用 **KMDF (Kernel-Mode Driver Framework)** 驱动模型：
- 简化的 WDF 编程模型
- 自动处理 PnP 和电源管理
- 内置的请求队列管理
- 良好的调试支持
- 与 Windows 存储栈良好集成

## 可选方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **虚拟总线+功能驱动** (本项目) | 灵活可控，无需硬件 | 开发复杂度较高 | 通用虚拟存储 |
| StorPort Virtual Miniport | 微软官方支持 | 需要 VMBus/Hyper-V | Hyper-V 环境 |
| RAM Disk (直接实现) | 实现简单 | 功能受限 | 简单内存盘 |
| iSCSI Initiator | 利用现有栈 | 需要网络配置 | 网络存储 |
