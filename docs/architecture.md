# 系统架构设计

## 整体架构

本项目采用 **虚拟总线驱动 + 虚拟 PDO** 架构，这是纯软件虚拟存储设备的最佳实践方案。

## 驱动架构说明

### 为什么不使用 StorPort Miniport？

StorPort Miniport 驱动模型主要设计用于真实硬件控制器，存在以下限制：
- 需要实际的硬件资源（中断、DMA、内存映射 I/O）
- 与 PnP 管理器的交互假定存在真实硬件
- 不适合纯软件模拟场景

### 采用的方案：虚拟总线 + 功能驱动

| 组件 | 文件 | 职责 |
|------|------|------|
| 虚拟总线驱动 | vnvmebus.sys | 作为根枚举总线，创建/管理虚拟设备 PDO |
| 功能驱动 | vnvme.sys | 实现 NVMe 控制器逻辑，处理 I/O 请求 |
| 用户态控制程序 | vnvmectl.exe | 创建/删除/配置虚拟磁盘 |

## 核心组件

### 1. 虚拟总线驱动 (vnvmebus.sys)
- 作为根枚举设备安装到系统
- 响应用户态 IOCTL 创建/删除虚拟设备
- 为每个虚拟 NVMe 设备创建 PDO
- 管理设备实例列表
- 处理 PnP 和电源管理事件

### 2. NVMe 功能驱动 (vnvme.sys)
- 附加到总线驱动创建的 PDO 上
- 实现完整的 NVMe 控制器模拟
- 处理来自存储栈的 SCSI/ATA 命令并转换
- 或直接实现 StorageDevice 接口

### 3. NVMe 控制器模拟器 (Controller Emulator)
- 控制器寄存器模拟 (CAP, CC, CSTS 等)
- 控制器状态机管理 (Disabled → Enabling → Enabled)
- 能力报告 (Capabilities)
- Identify 数据结构填充

### 4. 命令处理器 (Command Processor)
- Admin Command 队列处理
- I/O Command 队列处理
- 完成队列管理
- 中断模拟 (MSI-X 模拟)

### 5. 存储后端适配器 (Storage Backend)
- **内存后端**：使用非分页池内存，适合小容量测试
- **文件后端**：使用文件作为存储介质，支持持久化
- **VHD 后端**：利用 Windows VHD API，可挂载现有虚拟磁盘
- 可扩展接口设计，支持自定义后端

### 6. 配置管理器 (Configuration Manager)
- 注册表配置读取
- 运行时参数管理
- 命名空间配置
- 动态容量调整

## 驱动类型选择

采用 **KMDF (Kernel-Mode Driver Framework)** 驱动模型：
- 简化的 WDF 编程模型
- 自动处理 PnP 和电源管理
- 内置的请求队列管理
- 良好的调试支持
- 与 Windows 存储栈良好集成

## 可选方案对比

| 方案 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **虚拟总线+功能驱动** (本项目) | 灵活可控，无需硬件 | 开发复杂度较高 | 通用虚拟存储 |
| StorPort Virtual Miniport | 微软官方支持 | 需要 VMBus/Hyper-V | Hyper-V 环境 |
| RAM Disk (直接实现) | 实现简单 | 功能受限 | 简单内存盘 |
| iSCSI Initiator | 利用现有栈 | 需要网络配置 | 网络存储 |
